System Requirements

Before installing IDTrack, ensure your system meets these requirements:

Requirement

Details

Python

3.12 to 3.15

Operating Systems

Linux, macOS (Intel and Apple Silicon), Windows

Memory

Using a graph: 0.26 GB (cynomolgus) to 1.14 GB (human) after loading, plus your data. Building a graph: 0.6 GB (cynomolgus) to 4.5 GB (human) at the peak. See Time and Memory.

Disk Space

The tables a graph is built from stay in the local repository: 0.27 GB (cynomolgus), 0.65 GB (pig and rhesus), 2.1 GB (mouse), 5.3 GB (human) for a graph of snapshot release 115, plus the graph file itself (47 MB to 345 MB).

Network

HTTPS access to ftp.ensembl.org and rest.ensembl.org to build a graph (and for idtrack.API.resolve_organism() to learn the latest release); the Ensembl MySQL ports are optional (see Network Access: MySQL or HTTPS). Loading a graph that is on disk needs no network.

Note

Apple Silicon users (M1/M2/M3/M4): If h5py fails to install or import, install HDF5 first. See the Apple Silicon (M1/M2/M3/M4) Setup section below.

Install with pip

IDTrack is published on PyPI (it is not on conda-forge or bioconda). Install it into a fresh environment:

$ python -m venv idtrack-env
$ source idtrack-env/bin/activate      # Windows: idtrack-env\Scripts\activate
$ pip install idtrack

or into a conda/mamba environment, with pip:

$ mamba create -n idtrack-env -c conda-forge python=3.13
$ conda activate idtrack-env
$ pip install idtrack

Important

The release on PyPI, 0.0.5, is older than the version these pages describe: the changes listed under “Unreleased” in Changes are not in it, and it reads neither the graphs nor the table cache of this version (nor this version its). Until the next release, install this version from GitHub:

$ pip install "git+https://github.com/theislab/idtrack.git@main"

idtrack.__version__ does not tell the two apart before then (both say 0.0.5).

Apple Silicon (M1/M2/M3/M4) Setup

IDTrack stores its tables with h5py, which needs HDF5. When pip finds no pre-built h5py wheel for your Python and machine, it compiles h5py against an installed HDF5; installing HDF5 through conda-forge or Homebrew first gives it one. This is a one-time setup.

Step 1: Install HDF5

Choose one of these methods:

# Method 1: Using Mamba (recommended)
$ mamba install -c conda-forge hdf5

# Method 2: Using conda
$ conda install -c conda-forge hdf5

# Method 3: Using Homebrew
$ brew install hdf5

Step 2: Install IDTrack

$ pip install idtrack

Verification:

$ python -c "import h5py; print('HDF5 version:', h5py.version.hdf5_version)"

Tip

If you still encounter HDF5 errors after installation, ensure your Python environment was created after installing HDF5. Creating a fresh environment often resolves issues.

Creating a Dedicated Environment (Recommended)

Using a dedicated environment is a good practice for any Python project and makes it easier to manage your installation. IDTrack runs on Python 3.12 to 3.15.

Using Mamba or conda

# Create a new environment with Python 3.13
$ mamba create -n idtrack-env -c conda-forge python=3.13    # or: conda create ...

# Activate the environment
$ conda activate idtrack-env

# Install IDTrack (from PyPI, with pip)
$ pip install idtrack

Using venv + pip

# Create a new virtual environment
$ python -m venv idtrack-env

# Activate the environment
# On Linux/macOS:
$ source idtrack-env/bin/activate
# On Windows:
$ idtrack-env\Scripts\activate

# Install IDTrack
$ pip install idtrack

Development Installation

For contributors or users who want the latest development features.

Prerequisites

Ensure you have these tools installed:

  • Git for version control

  • Poetry for dependency management

$ pip install poetry poetry-plugin-export

Clone and Install

Step 1: Clone the repository

$ git clone https://github.com/theislab/idtrack.git
$ cd idtrack

Step 2: Install with Poetry

$ make install

This installs IDTrack in development mode with all dependencies, including development and testing tools.

Step 3: Verify installation

$ poetry run python -c "import idtrack; print(f'IDTrack {idtrack.__version__}')"

Alternative: Install from Tarball

For users who want the code of the main branch without cloning the repository:

$ curl -OJL https://github.com/theislab/idtrack/tarball/main
$ tar -xzf theislab-idtrack-*.tar.gz
$ cd theislab-idtrack-*
$ pip install .

Verifying Your Installation

After installation, verify that IDTrack is working correctly by running this verification script:

from pathlib import Path
import idtrack

# Pick a stable, writable cache directory (reused across runs)
local_repo = Path("./idtrack_cache").resolve()
local_repo.mkdir(parents=True, exist_ok=True)

# Print version information
print(f"IDTrack version: {idtrack.__version__}")

# Test API initialization
api = idtrack.API(local_repository=str(local_repo))
print("API initialized successfully")

# Test organism resolution
organism, release = api.resolve_organism("human")
print(f"Resolved organism: {organism}")
print(f"Latest Ensembl release: {release}")

print("\nInstallation verified successfully!")

Expected output:

IDTrack version: 0.0.x
API initialized successfully
Resolved organism: homo_sapiens
Latest Ensembl release: 116

Installation verified successfully!

If you see output similar to this, your installation is complete and working (the latest release is the one Ensembl serves on the day you run it).

Network Access: MySQL or HTTPS

IDTrack reads Ensembl’s core databases in one of two ways: from the public MySQL service (ensembldb.ensembl.org, ports 3306, 5306 and 3337) or from the MySQL dumps on https://ftp.ensembl.org/pub/. Many institutional networks and HPC clusters block the MySQL ports; HTTPS is enough. The access mode is chosen with the environment variable IDTRACK_ENSEMBL_ACCESS or the attribute idtrack.DB.ensembl_access (which wins when set):

Mode

Behaviour

auto (default)

Each MySQL port is probed once per Python process, with a short timeout. Releases on a port that answers are read over MySQL; everything else, and everything after a MySQL connection fails, is read from the HTTPS dumps.

https

MySQL is never contacted; every table is read from the HTTPS dumps.

 
$ export IDTRACK_ENSEMBL_ACCESS=https

import idtrack

idtrack.DB.ensembl_access = "https"  # or "auto"

What differs between the modes: nothing in the tables: both read the same Ensembl tables, with the same rows, values and column types. The dump reader decodes MySQL’s escaping (tabs, newlines and backslashes inside fields, NULL) so that each row holds what the MySQL server returns, and takes the column types from the table definitions of the dump, so a text column of digit strings stays text. The HTTPS path downloads whole compressed tables, so it is slower per table than a MySQL query (seconds to a minute per large table), but it needs no open port. In auto mode a blocked port costs one short probe per process, not one per table, and a port whose connection fails is not tried again for ten minutes (then after twice as long, up to a day; the tables come over HTTPS meanwhile, with a warning; this costs only speed). A query or data error of the MySQL server is raised, not answered over HTTPS.

If you route IDTrack through an SSH tunnel with idtrack.ConnectionBridge, starting and stopping the bridge forgets the probe results, so the ports are probed again through the new route.

Slow networks, timeouts and retries. Every request to Ensembl REST (organism names and the latest release) waits idtrack.DB.connection_timeout seconds to connect (default 15) and idtrack.DB.reading_timeout seconds for the answer (default 60; it also applies to the HTTPS dumps), and is tried idtrack.DB.rest_attempts times (default 3) when it times out, the connection fails, or Ensembl answers 429 or 5xx. When every attempt fails, idtrack.EnsemblRestError (a ConnectionError) names the URL, the timeouts and what to change; a download of the dumps that keeps failing raises idtrack.EnsemblDownloadError (also a ConnectionError), and a release that cannot be listed is an error, never read as “Ensembl has no such release”. On a network where Ensembl answers slowly, raise the timeouts before the first call:

import idtrack

idtrack.DB.reading_timeout = 120
idtrack.DB.rest_attempts = 5

The network is needed only to download, and to learn which release is the latest: the formal name, the short name and the assembly names of a supported organism ("homo_sapiens", "Homo sapiens", "human", "GRCh38") resolve without it, and a graph file on disk loads and converts without it (see Reusing Built Graphs), as does a harmonization whose graph is on disk. The local repository may be read-only: it then serves the tables and graphs it holds, and a table that would have to be computed raises PermissionError naming the folder. An HTTPS proxy is honoured through HTTPS_PROXY.

Optional Dependencies

IDTrack has optional dependencies for advanced features:

External Mapping Backends

For cross-database identifier mapping using external services:

# Install the optional backends via Python extras (recommended)
$ pip install "idtrack[external-mappers]"

# Or install only the libraries you need
$ pip install gget mygene pybiomart gprofiler-official

Ortholog Analysis

For cross-species ortholog analysis with sequence alignment:

$ pip install "idtrack[ortholog]"

Protein Embeddings

idtrack._external_mappers._ortholog.align_ortholog_pair_with_features() can add protein-language-model embedding features to an ortholog alignment. They need torch and transformers; with them installed, the model named by embedding_model_name (facebook/esm2_t12_35M_UR50D by default) is downloaded from Hugging Face on first use. Without them, or with embedding_model_name=None, those features are left empty (with verbose=True a warning says why) and the other alignment features are computed.

$ pip install "idtrack[embeddings]"

All Optional Dependencies

Install all optional dependencies at once:

$ pip install "idtrack[all-external]"

Troubleshooting

Common Installation Issues

HDF5 / h5py import errors

This usually indicates an HDF5 binary compatibility issue. Install h5py from conda-forge in a fresh environment, then IDTrack with pip:

$ mamba create -n idtrack-env -c conda-forge python=3.13 h5py
$ conda activate idtrack-env
$ pip install idtrack

SSL Certificate errors during download

If IDTrack encounters SSL errors when downloading external databases:

# Update certificates
$ pip install --upgrade certifi

# On macOS, you may also need:
$ /Applications/Python\ 3.x/Install\ Certificates.command

Permission errors during installation

# Option 1: Use --user flag with pip
$ pip install --user idtrack

# Option 2: Use a virtual environment (recommended)
$ python -m venv idtrack-env
$ source idtrack-env/bin/activate
$ pip install idtrack
