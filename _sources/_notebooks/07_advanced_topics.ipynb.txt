    "## 7.1 — Custom External Database Inclusion\n",
    "\n",
    "The external YAML is an explicit **contract**: it defines which external namespaces are allowed to influence your graph.\n",
    "\n",
    "Two common profiles:\n",
    "\n",
    "- **Strict profile:** a small allowlist, lower ambiguity, smaller downloads.\n",
    "- **Broad profile:** a larger allowlist (the shipped default is one), more coverage, but more ambiguity.\n",
    "\n",
    "The YAML of a local repository has a fixed name, `<organism>_externals_modified.yml` (without it, the shipped default is used). A graph\n",
    "file records the selection of external databases it was built from: loading it under another selection raises\n",
    "`idtrack.errors.GraphMismatchError` instead of answering from a graph of the other profile. So keep **one local repository per profile**: each\n",
    "holds its YAML, its tables and its graph.\n",
    "\n",
    "The next cell writes two profiles with `idtrack.build.default_externals.apply_allowlist`, which switches on exactly the\n",
    "`{form: {database: [assembly keys]}}` entries of an allowlist in a template (the shipped templates list every database Ensembl has\n",
    "for the organism, per form: gene, transcript, translation) and reports allowlisted names the template does not have. It writes\n",
    "nothing over an existing YAML of your local repository."

    "## 7.2 — Programmatic YAML Management\n",
    "\n",
    "For pipelines you often want YAML changes to be **scriptable** and **repeatable**.\n",
    "\n",
    "A safe automation pattern:\n",
    "\n",
    "1. Start from a template YAML (shipped in `idtrack/default_config/`, or generated as in Part 2).\n",
    "2. Apply a curated allowlist in code (`apply_allowlist`).\n",
    "3. Write the resulting YAML to a file you commit alongside your pipeline, and copy it into the local repository of the run.\n",
    "\n",
    "The next cell shows a reusable helper that:\n",
    "- reads a template YAML\n",
    "- applies an allowlist\n",
    "- writes a modified YAML to the path you give (never over a file you did not name)\n",
    "\n",
    "> **Tip:** Keep allowlists per organism in your pipeline repository (as Python dicts or a small TOML/YAML). That makes your\n",
    "> configuration reviewable. `idtrack.build.default_externals.DEFAULT_EXTERNALS` holds the allowlists of the shipped files."

    "## 7.3 — Troubleshooting & Diagnostics\n",
    "\n",
    "Common failure modes (and what they usually mean):\n",
    "\n",
    "- **Permission errors in `IDTRACK_LOCAL_REPO`:** your cache directory is not writable.\n",
    "- **REST timeouts:** network issues or Ensembl REST is temporarily slow.\n",
    "- **MySQL connection errors:** outbound MySQL ports may be blocked; IDTrack probes a port once and, when it fails, uses the HTTPS/FTP\n",
    "  dumps for the next ten minutes or longer (the same tables, rows and values, slower per table). Set `IDTRACK_ENSEMBL_ACCESS=https`\n",
    "  (or `idtrack.settings.configure_ensembl(access='https')`) to skip MySQL entirely. Port `3337` is Ensembl's archive server (GRCh37 from release 79; IDTrack reads it for human GRCh37 only; its\n",
    "  frozen copies of other assemblies carry later release numbers and are not used).\n",
    "- **`idtrack.errors.GraphMismatchError` when loading a graph:** the graph file in your local repository was built from another selection of\n",
    "  external databases, another organism table or by an older graph format than you ask for now; the message names the differences.\n",
    "  Use another local repository, or build again with `API.build(..., rebuild=True)`.\n",
    "- **`idtrack.errors.EnsemblDownloadError` / `idtrack.errors.EnsemblRestError`:** Ensembl did not answer after the retries; the message names the URL.\n",
    "  A release is never silently skipped because a request failed.\n",
    "- **A warning that releases have no entry in the external YAML:** your external YAML does not include every release of the snapshot\n",
    "  window; a graph built so has no external identifiers at those releases. Extend the file with `ExternalDatabases.extend_modified_yaml`\n",
    "  (Part 2, section 2.6).\n",
    "- **Unexpected 1→n explosion:** your external allowlist is too broad or contains promiscuous namespaces.\n",
    "\n",
    "The next cell is a compact diagnostic report you can paste into issues or lab notes."

    "        except OSError as e:\n",

    "## 7.4 — Integration Patterns\n",
    "\n",
    "IDTrack works best in pipelines when you make the snapshot boundary and cache location explicit.\n",
    "\n",
    "Key ideas:\n",
    "\n",
    "- Set `IDTRACK_LOCAL_REPO` to a stable, shared path (per project or per compute environment).\n",
    "- Build snapshots once, then reuse them across jobs (a graph file loads without network and is only read, so parallel jobs can share\n",
    "  one local repository).\n",
    "- Pin the snapshot release in the pipeline: the graph file name, and the answers, depend on it.\n",
    "- Store your external YAML alongside your pipeline so the configuration is reviewable.\n",
