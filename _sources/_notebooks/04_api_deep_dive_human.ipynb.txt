    "### 4.2.4 Understanding the result\n",
    "\n",
    "A result is an `idtrack.results.ConversionResult` (a frozen dataclass; its docstring lists every field):\n",
    "- `query_id`: exactly what you typed\n",
    "- `graph_id`: the identifier of the graph it was read as; `match`: how it matched (`exact`, `case`, `separator`, `version`,\n",
    "  `synonym:...`, `version_newer_than_graph`)\n",
    "- `from_release`: the release it was read at; `from_release_inferred`: chosen by IDTrack (no `from_release` given);\n",
    "  `from_release_fallback`: the `from_release` you gave does not hold the identifier, so it was read where the graph holds it\n",
    "- `candidates`: every target the search reached, ranked, the best marked (`candidate.best`); `targets('best')` and\n",
    "  `targets('all')` are the target ids of the two views (`view('best')`, `view('all')`)\n",
    "- `tie`: the best answer is shared by several genes or targets equal in all evidence; `decided_by`: the criterion that put the\n",
    "  best answer before the runner-up\n",
    "- `alternative_locus_genes`: copies on alternative loci and patches reported apart from the answer\n",
    "- `status`: `converted`, `tie`, `no_target`, `not_found` (input didn’t match any identifier of the graph), `unknown_version`\n",
    "  (`known_versions` lists the versions that exist), `no_conversion` (input matched, but no gene at the target release descends\n",
    "  from it) or `error`; `reason` says why a result has no candidate\n",
    "- `no_target`: genes were reached, but none has an id in the requested database (the targets are then their Ensembl ids);\n",
    "  `no_target_genes`: genes without such an id when others have one\n",
    "\n",
    "Important: there can be 0, 1 or many targets, because ambiguity is real and common. Every result is strict JSON with\n",
    "`result.to_dict()`, and `ConversionResult.from_dict(...)` reads it back."
   ]

    "## 4.5 — Advanced Conversion Options\n",
    "\n",
    "`api.convert(...)` checks the arguments and reads the string, then calls the engine, `api.engine.convert(...)`\n",
    "(`idtrack.engine.Track.convert`).\n",
    "\n",
    "Use the high-level API most of the time; it already takes `allow_bridges`, `budget_states` and `budget_seconds`. The engine is\n",
    "strict where the API is forgiving: a `from_release` at which the identifier does not exist raises\n",
    "`idtrack.errors.InactiveAtReleaseError` (naming the releases where it exists), and an unknown version raises\n",
    "`idtrack.errors.UnknownVersionError`.\n",
    "\n",
    "### 4.5.1 Best vs all\n",
    "\n",
    "- `result.view('best')` is the best answer: one target, or the targets that are equal in all evidence, as a tie (`tie=True`), in\n",
    "  a fixed order.\n",
    "- `result.view('all')` is every target reached, best first (useful for ambiguity-aware pipelines); `result.decided_by` names the\n",
    "  criterion that put the best answer before the runner-up.\n",
    "\n",
    "### 4.5.2 Controlling external bridging\n",
    "\n",
    "The search follows Ensembl's history first. Only when that leads to no gene at the target release does it pass through an external\n",
    "identifier or a transcript that two genes carried (a bridge): at most two bridges, the fewest possible, in the order of time, never\n",
    "through clone-based names or hyper-connected identifiers. `candidate.bridges` says how many bridges were used. Switch bridging off\n",
    "with `allow_bridges=False`. The search is bounded: each state is visited once, and a call that needs more than its budget\n",
    "(`idtrack.settings.SearchSettings`: 200,000 states and 30 s by default; `budget_states=` and `budget_seconds=` of a call) raises\n",
    "`idtrack.errors.SearchBudgetExceededError`.\n",
    "\n",
    "### 4.5.3 Hyperconnected nodes\n",
    "\n",
    "Some external identifiers are carried by many genes at the same time (RFAM families, `U6`, `5S_rRNA`, snoRNA names): more than\n",
    "the hyper-connectivity threshold of the graph (`idtrack.settings.GraphSettings`, 5) genes in one release. They name a kind of gene, not a gene, so they are never used as bridges\n",
    "and are not counted as annotation of a gene. They can still be queried and returned.\n",
    "\n",
    "### 4.5.4 Assembly-aware conversions\n",
    "\n",
    "In IDTrack, genome assemblies are part of the graph. This is crucial when you integrate datasets that were annotated with different\n",
    "references (for example, a GRCh37-based GTF and a GRCh38-based GTF).\n",
    "\n",
    "A conversion uses, at every release, the assembly Ensembl maintained at that release (human: NCBI36 up to release 54, GRCh37 up to\n",
    "75, GRCh38 from 76). The parallel GRCh37 of later releases is not walked; its ids are in the graph as ids to convert from. The final\n",
    "conversion into a database is made on the assembly of the target release, so a conversion to release 70 returns the HGNC symbols of\n",
    "GRCh37 at release 70.\n",
    "\n",
    "Practical consequences:\n",
    "- You can feed identifiers originating from older builds and harmonize them into one target space (a release of your snapshot).\n",
    "- External databases are read for the assembly they belong to; an id is returned as its database wrote it at the target release.\n",
    "\n",
    "Example (advanced):\n",
    "```python\n",
    "api.convert(\n",
    "    'TP53',\n",
    "    to_release=SNAPSHOT_RELEASE,\n",
    "    final_database='HGNC Symbol',\n",
    "    from_database='HGNC Symbol',  # read the identifier as an id of this database only\n",
    "    explain=True,\n",
    ")\n",
    "```"
