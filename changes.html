Changes

This page lists the changes that affect users, newest first. Version numbers follow pyproject.toml.

0.1.0

This version changes what conversions return where 0.0.5 returned wrong genes, how graphs are stored, the layout of the package and its whole API. Graphs and table caches of 0.0.5 are not read. Install it from GitHub until it is published on PyPI (Installation).

The package and its API

  • Public modules. The package is laid out by responsibility, in layers that import only downwards: idtrack.errors, idtrack.settings and idtrack.ids (the graph’s vocabulary and the rule of <id>.<version>) at the bottom; idtrack.organisms (the organism table); idtrack.graph (the graph and its file, idtrack.graph.files); idtrack.engine (the search and its ranking); idtrack.results and idtrack.api; idtrack.harmonize; idtrack.build (Ensembl access, the table store, the externals configuration, the graph builder); idtrack.checks (the self-tests). No module name starts with an underscore any more where users read it, and import idtrack then idtrack.API.load(<graph file>) imports none of the build stack (pandas, h5py, PyMySQL, PyYAML).

  • Loading and building are separate calls. idtrack.API.load() loads a graph file by its path and never builds or uses the network; a missing or unreadable file is an idtrack.errors.GraphFileError that names it. idtrack.API.build() builds a graph from Ensembl’s tables (or loads the file of the same graph from the local repository; rebuild=True replaces it). idtrack.API.graph_path() says where the file of a graph is, idtrack.API.database_manager() gives the manager of the tables. API(graph) wraps a graph in memory. API(local_repository=...), API.build_graph, API.get_database_manager and the attribute API.track are gone.

  • One conversion call, typed results. idtrack.API.convert() returns an idtrack.results.ConversionResult (a frozen dataclass; to_dict() is strict JSON and ConversionResult.from_dict reads it back) with every candidate the search reached (idtrack.results.Candidate), ranked, the best marked: result.view("best") and result.view("all") are views of the one search, so the argument strategy and the second search it cost are gone. Each candidate carries its ranking record (final confidence, bridges, gap, support of the entry gene, score, being the query itself, steps, the annotation counts where compared), and result.decided_by names the criterion between the best answer and the runner-up. result.status (converted, tie, no_target, not_found, unknown_version, no_conversion, error) and result.reason (why a result has no candidate, idtrack.results.REASONS) replace the flags no_corresponding, no_conversion and ambiguous. convert_identifier is gone.

  • The path as data. With explain=True the result has path, an idtrack.results.ExplainedPath: every node (kind, label, databases, active releases, assemblies, the releases outside the reference sequence) and every step (kind, releases, Ensembl’s score, splits and merges, databases and assembly of a cross-reference, the assemblies on both sides of a history step, the reason it was taken as a code of idtrack.results.STEP_REASONS) once per conversion; candidates refer to their steps by index. Nodes and databases are named as the graph names them (a synonym with the prefix synonym_id::). The untyped edge lists of the_path are gone.

  • Batches. idtrack.API.convert_many() (was convert_identifier_multiple) accepts any sequence of strings (a list, a NumPy array, a pandas Index; a single string is refused) and never stops on one identifier’s error: the item has status == "error" and the error in result.error. It shows no progress bar unless progress=True. idtrack.API.classify() (was classify_multiple_conversion) bins the results of one view, and idtrack.API.classification_summary() (was binned_conversion_summary; print_binned_conversion is gone) writes the counts.

  • What a graph holds, and names. idtrack.API.describe() (organism, releases, assemblies with their names and the releases they serve, databases, the package version and commit that built the graph) needs no network. idtrack.API.genes_named() (which genes a name names, per database and release) and idtrack.API.names_of() (the names of a gene) are public, as idtrack.graph.TheGraph.genes_named() and idtrack.graph.TheGraph.names_of(). Renamed: graph_releases and list_ensembl_releases to idtrack.API.releases(), valid_final_databases to idtrack.API.final_databases(), list_external_databases to idtrack.API.external_databases(), list_external_databases_by_assembly to idtrack.API.databases_by_assembly() (string keys, strict JSON), external_database_forms to idtrack.API.database_forms(), infer_identifier_source to idtrack.API.infer_source() (its modes release and assembly_release were ensembl_release and assembly_ensembl_release), resolve_organism (with the network) to idtrack.API.ensembl_organism(); list_genome_assemblies is gone: the assemblies are in idtrack.API.describe().

  • Errors. Every error idtrack raises is an idtrack.errors.IdtrackError: input errors (idtrack.errors.InputError, with the argument and the valid values: unknown organism, release, assembly, database, identifier, a missing value, an inactive release, an unknown version, a wrong type or value; each also a ValueError, or a TypeError for a wrong type), graph-file errors (idtrack.errors.GraphFileError, idtrack.errors.GraphMismatchError), idtrack.errors.SearchBudgetExceededError, build errors (idtrack.errors.BuildError: Ensembl access, schema, table format, history, externals) and idtrack.errors.IntegrityError (a bug or a damaged file, never the caller’s input).

  • Settings. The budget of a search and the rules of bridges are a idtrack.settings.SearchSettings held by an API (API.load(path, search=...)), and a call can give its own budget (budget_states, budget_seconds; the engine takes the call’s settings, search); the hyper-connectivity threshold and the cache bounds are a idtrack.settings.GraphSettings of a loaded graph (graph_settings wherever one is passed). How Ensembl is reached (access mode, timeouts, retries, hosts) is set once per process with idtrack.settings.configure_ensembl(). The class attributes Track.search_budget_states, Track.search_budget_seconds, Track.non_bridging_databases, TheGraph.genes_at_once_threshold and TheGraph.cache_sizes are gone.

  • The organism table and the vocabulary. The class DB is gone: the organism table and its functions are idtrack.organisms (ORGANISM_TABLE, SYMBOL_DATABASES, ALIASES, register_organism(), first_release(), resolve_organism() without the network, …), the node types and markers are idtrack.ids, the network settings idtrack.settings.

  • Self-tests. idtrack.checks.GraphChecks (GraphChecks(graph, database_manager)) replaces TrackTests (and API.build_graph(..., return_test=True)); it holds an engine rather than being one. The checks keep their names and return idtrack.checks.CheckResult; how_many_corresponding_path_ensembl is gone, and history_travel_testing_random always returns its result.

  • One name per concept. The same thing has the same name in every call: snapshot_release (was ignore_after of DatabaseManager and graph_file_path, graph_last_ensembl_release of HarmonizeFeatures, TheGraph.last_release), first_release (was ignore_before), to_release (was target_ensembl_release), release (was ensembl_release of DatabaseManager and ExternalDatabases, ens_rel), organism (was organism_name), identifier/identifiers (was from_id, identifier_list, dataset_ids), name for idtrack.graph.TheGraph.genes_named() (was text), final_database (was to_database), serving_assembly for the assembly that serves a release (was TheGraph.backbone_assembly and the engine’s primary_assembly; “primary” names only the graph’s own assembly), allow_bridges and bridge_limit (were go_external and jump_limit), progress for a progress bar (was verbose of the self-tests) and verbosity (was verbose_level of HarmonizeFeatures), assembly for the assembly an argument names (was genome_assembly of API.database_manager, DatabaseManager, ExternalDatabases and GraphMaker.load_graph; the graph file keeps its stored attribute genome_assembly) and TheGraph.available_assemblies (was available_genome_assemblies), forms (was form_list), database_manager (was db_manager), strategy for the best answer or all candidates also in the self-tests (was prioritize_to_one_filter), from_release, from_database and to_release in idtrack.graph.TheGraph.resolve_name() and in is_final_external_conversion_robust (final_database, to_release), from_release_by_dataset and from_database_by_dataset of HarmonizeFeatures (were source_releases and source_databases), features of unify_multiple_anndatas (was mode), external_databases of idtrack.results.GraphDescription and idtrack.results.AssemblyDescription, and graph_id of idtrack.engine.Conversion (as in idtrack.results.ConversionResult).

  • The engine. Track(graph) is built from a graph (Track.from_graph and the constructor that built a graph are gone); idtrack.engine.Track.convert() returns an idtrack.engine.Conversion with the ranked candidates. Track.get_possible_paths and Track.calculate_node_scores are gone. Track is no longer importable from idtrack itself. Each argument is checked by one rule with one message: the engine’s checks (a release of the graph; a database of the graph at the target release, matched without letter case and surrounding white space), which idtrack.API uses before it hands the checked values to the search; the API also reads a user’s identifier (surrounding white space removed, an empty string refused), where the engine reads the string as it is given.

  • Harmonization is an extra. pip install "idtrack[harmonize] @ git+https://github.com/theislab/idtrack.git" brings anndata and scipy for idtrack.harmonize.HarmonizeFeatures; without them that class raises an ImportError that names the extra. It is imported by its name (from idtrack import HarmonizeFeatures): it is not in __all__, so that from idtrack import * works on the plain install. Its pure core, idtrack.harmonize.convert_features(), idtrack.harmonize.feature_table() and idtrack.harmonize.output_plan(), needs pandas only.

  • Removed: the external-database mappers (idtrack._external_mappers: the wrappers of MyGene, g:Profiler, gget, BioMart and the ortholog alignment, with their extras external-mappers, ortholog, embeddings and all-external), the connection bridge (ConnectionBridge, and the dependency PySocks: every graph builds over Ensembl’s HTTPS dumps where MySQL is blocked), and the folder reproducibility/ of the repository (the manuscript’s notebooks and scripts stay reachable at the tag manuscript-2026-03).

  • The version is 0.1.0, written in pyproject.toml only and read from the installed package’s metadata (idtrack.__version__; unknown for a source folder that is not installed). A graph file records the version that built it and, where it was known, the git commit (package_commit; idtrack.API.describe()).

What a user of 0.0.5 must do

  • Build your graphs again. Graph files of 0.0.5 (graph_<organism>_min<a>_max<b>_narrow.pickle) and its table cache (<organism>_assembly-<key>.h5) are not read; idtrack.API.build() builds the graph from Ensembl’s tables (downloaded again) and writes the new files beside the old ones, which you can then delete. A build takes from 6 minutes (cynomolgus) to 2 hours (human) and at most 4.5 GB of memory (previously up to 11 hours and 65 GB for human); see “Time and Memory” in Quickstart.

  • Bring your code to the API described under “The package and its API” above; the arguments and attributes of 0.0.5 listed under “Removed” below are gone.

  • Use Python 3.12 to 3.15.

  • Pin the snapshot release in scripts (API.build("homo_sapiens", 115, local_repository)) rather than building at idtrack.API.ensembl_organism()’s latest release, which changes with every Ensembl release.

  • Expect other answers where 0.0.5 was wrong (below). Results of 0.0.5 that you keep cannot be reproduced with this version; record the version with your results.

Conversions: what an identifier means

  • The starting release. With from_release the identifier is read at that release. Without it, it is read at the target release when it exists there, and otherwise at the latest release at which it exists. Previously an id without from_release was read at the oldest period in which it existed, so that, for example, a current human gene id without version converted to another gene in 2,557 of 78,899 cases (NFYA to NFYB), and 17 % of human NCBI gene ids and 1 to 2 % of symbols returned the wrong gene. The rule is the same for Ensembl ids, symbols and other external ids, and the result says which release was used (from_release, from_release_inferred).

  • A from_release at which the graph does not hold the identifier. idtrack.engine.Track.convert() raises idtrack.errors.InactiveAtReleaseError, which names the releases at which the identifier exists (previously the answer came silently, as if no release had been given). idtrack.API.convert() reads the identifier where the graph holds it instead and flags the result (from_release_fallback, from_release_given).

  • What a string means. When a string can mean several nodes (a symbol that was the name of one gene and is a synonym of another today), the one that exists at the release asked about is taken (from_release, without it the snapshot release); an Ensembl stable id is never passed over for a synonym spelt the same. An identifier exists at a release only on the genome assembly that Ensembl maintained at that release: the names that human GRCh37, listed beside GRCh38 with its annotation of release 75, still carries do not exist today (3,277 of them are a synonym of a gene on GRCh38 today; read as the old name, 638 returned other genes than the synonym’s). Then the string is matched exactly, then ignoring letter case, then taking -, _ and . as one character, then (only for ids of sequence-accession databases such as RefSeq and UniProt) without a version the graph does not hold; each step on names and then on synonyms. A name typed as a database wrote it at the release it is read at is an exact match of that name, also where the database writes it in another letter case today or two databases write it in two ways (at release 75 MGI wrote the mouse gene Bap1 and UniProt wrote it BAP1), and is not taken for another gene’s synonym spelt the same. The new result field match says how it matched. The engine reads a string by the same rule (idtrack.graph.TheGraph.resolve_name()): Track.convert("X") no longer takes a string that happens to be the name of a node as that node; to convert a particular node whatever the release, give a from_release at which it exists. Previously a dash-or-underscore suffix was cut off any string (SNORD116_10 became SNORD116: 10,506 human ids resolved to another gene), the least-connected spelling of an id written in several cases was kept, and every combination of separators was tried (minutes for a string with 20 of them); the lookup now costs microseconds whatever the string. Surrounding white space is ignored.

  • Versions. An Ensembl id with a version that the graph does not hold is not answered with another version’s gene: the result has no target, and known_versions lists the versions that exist (the engine raises idtrack.errors.UnknownVersionError). A version higher than all the graph holds, of an id still active at the snapshot, may come from a newer release: it is read as the latest version and reported as match == "version_newer_than_graph". Previously any unknown version was answered with the gene of the id without version. Transcript and translation ids without version are now found (previously none was).

  • Ties. The best answer is one target, or, when several genes or targets are equal in all evidence, all of them, with tie true, ordered by the mapping score of each to the gene the identifier was read as and then by gene and target id. Previously several targets could come in an order that changed between runs (the hash seed), so the first target could be another gene in the next run. Every list of a result is now in a defined order, and two runs give the same answer. A tie is judged among the genes that have an id in the requested database (the others are named in no_target_genes).

  • Every answer, best first. Every candidate is ranked: the genes of the best answer first, then the others by their evidence, so the first candidate is the first target of the best answer.

  • Copies on alternative loci, patches and LRG records (human; mouse GRCm38) are marked in the graph from Ensembl’s sequence regions. When an identifier leads to a gene of the reference sequence, the copies are left out of the answer and listed in the new result field alternative_locus_genes; when it leads to copies only, they are the answer. idtrack.graph.TheGraph.is_non_reference() and idtrack.graph.TheGraph.non_reference_releases() tell where a gene is such a copy. (Previously LRG records were left out by their id prefix, without saying so.)

  • A gene id is its own answer. A queried Ensembl gene id that exists at the target release is answered with itself: its own version comes first in the result, is never set apart as a copy, and is the answer of the best answer whatever else its history reaches; the other candidates follow it.

  • A database named for the identifier. from_database of idtrack.API.convert() (and of idtrack.engine.Track.convert()) reads the identifier as an id of that database: only the genes that database attaches it to are entered, and between them the evidence of every database still counts. A symbol that two databases give to two genes is a tie without it and that database’s gene with it; a symbol that the named database gives to two genes, of which other databases confirm one, is that one.

  • The databases behind an identifier. The result field from_databases names every database that attaches the identifier to its genes at the release it was read at, whether to a gene itself or to one of its transcripts or translations, and the support of a gene (entry_support of idtrack.engine.Track.convert()) counts all of them.

  • History. Ensembl’s id history (mapping_session) is checked against the ids of each release when a graph is built; a session recorded with wrong releases is placed where its ids change (pig 106 to “104” is 106 to 107; human 114 to “114” is 114 to 115), each correction is recorded in the graph file and logged, and a session that fits no pair of releases stops the build (idtrack.errors.HistoryValidationError). Previously 1,123 pig gene ids converted to ids that do not exist at the target. The human graph now has the id history before release 76, which the previous table cache could omit.

  • Search. The search follows Ensembl’s history first; only when that leads to no gene does it pass through an external id or transcript that two genes carried (at most two such bridges, the fewest possible, in the order of time, never through clone-based names or through ids that more than five genes carry at once). It is bounded: every state is visited once, and a call has a budget (idtrack.settings.SearchSettings) past which it raises idtrack.errors.SearchBudgetExceededError. The previous search enumerated paths: some conversions ran for more than 40 minutes, and strategy="best" raised unexpected!2 for 2.7 % of mouse gene ids.

  • Assemblies. A conversion uses, at each release, the assembly Ensembl maintained at that release (human GRCh38 from 76; the parallel GRCh37 is not walked, its ids are converted from). A conversion to a release of an earlier assembly returns that assembly’s ids (previously none, e.g. 0 of 2,981 mouse symbols at release 102), and an id is returned as the database wrote it at the target release (IFN-omega-4 for UniProt, IFN-OMEGA-4 for NCBI). A graph’s external ids are named after the spelling of the latest release in which they exist (PKD1, not pkd1).

  • Archive copies. Ensembl’s archive server (MySQL port 3337) carries older assemblies forward under later release numbers (rhesus MMUL_1, pig Sscrofa10.2 for releases 90 to 99, mouse GRCm38); these frozen copies are not part of any graph, so a graph built over MySQL equals one built over HTTPS. Port 3337 is read for human GRCh37 only.

Results of the API

  • Results are plain data: json.dumps works on every result (previously NumPy booleans and tuple-keyed paths).

  • New fields of a result (idtrack.results.ConversionResult): match, known_versions, from_release (the release used), from_release_inferred, from_release_given, from_release_fallback, from_databases, to_release, tie, alternative_locus_genes, no_target_genes (genes reached that have no id in the requested database while others have) and error; the candidates and the explained path are described above.

  • Every argument is checked before the search: the identifier (a non-empty string), the releases (integers of the graph: idtrack.API.releases(); previously releases the graph does not hold were answered), the final database (idtrack.API.final_databases(), case ignored; previously checked only when the identifier was found). An invalid argument raises an idtrack.errors.InputError naming it.

  • idtrack.API.convert_many() checks all items first (positions named), converts each distinct identifier once, and records an error of one identifier on that item instead of losing the batch.

  • idtrack.API.releases() returns the graph’s releases (pig 56 to 115; previously the primary assembly’s releases only, 90 to 115); the methods that list databases and assemblies return new sorted lists.

  • idtrack.API.infer_source() returns a list: every origin tied for the highest count, or all origins with their counts; it raises idtrack.errors.UnknownIdentifierError when no identifier is in the graph (previously IndexError).

  • idtrack.API.classify() counts a query that converts to itself (without version, in another case) as unchanged; previously every query without version counted as “changed”.

  • idtrack.API.configure_logger() configures the "idtrack" logger only (previously it called logging.basicConfig on the root logger); every module logs under idtrack.<module>.

  • import idtrack imports nothing heavy; idtrack.API does not import anndata or scipy.

  • Errors a caller may want to catch are exported (idtrack.errors, above).

Graph files

  • A graph is one .npz file of arrays and JSON, named graph_<organism>_assembly<key>_min<first>_max<snapshot>_narrow.npz; it holds no pickle, so loading it executes no code. It records what it is (format version, package version, organism, primary assembly, window, snapshot, forms, the selection of external databases that takes effect, the organism table, the tables it was built from, the history corrections, build date, content digest: graph.manifest). A file that holds another graph than the one asked for raises idtrack.errors.GraphMismatchError naming the differences and how to build the graph again (previously it was loaded silently, so a graph of another assembly or of another externals YAML answered for this one).

  • idtrack.API.load() loads a graph file with no table, no idtrack.build.DatabaseManager and no network. Loading takes 1 to 5 s and holds 0.26 to 1.14 GB (human: 4.3 s and 1.14 GB; previously 206 s and 35 GB, 50 GB with the caches); nothing is computed in advance.

  • A graph is deterministic: built twice from the same tables, under different hash seeds, it has the same content digest (graph.manifest).

  • Tables are stored one file per table (idtrack_tables/<organism>_assembly-<key>/ens<release>_<table>.h5), each written to a temporary file and renamed, so an interrupted run leaves every stored table readable (previously one HDF5 file per assembly, which a killed writer could leave unopenable). A table’s file name and content record what it depends on (the release window of the id history, the databases the externals YAML enables): changing the YAML or the window no longer serves a stale table, and nothing needs to be deleted by hand. A read-only repository serves the tables it holds.

Organisms

  • Supported: human, mouse, pig, rhesus macaque (macaca_mulatta; assemblies Mmul_10, Mmul_8.0.1 and MMUL_1, keys 10, 801 and 1) and cynomolgus macaque (macaca_fascicularis; Macaca_fascicularis_6.0 and 5.0, keys 6 and 5). Ensembl names the MMUL_1 and Mmul_10 core databases alike (macaca_mulatta_core_<release>_10); MMUL_1 therefore has the key 1. See the Supported Organisms table in Quickstart.

  • Organisms are declared in one table, idtrack.organisms.ORGANISM_TABLE; idtrack.organisms.register_organism adds or replaces one for the running session (see “Adding Organism Support” in Contributor Guide). Each organism declares short names ("human", "mouse", "pig", "rhesus", "cynomolgus", idtrack.organisms.ALIASES) that resolve without the network and win over Ensembl’s other species of that name ("pig" is also the common name of every pig breed in Ensembl). Assembly names ("GRCm38") resolve to their organism.

  • Organisms whose Ensembl ids carry no versions are not supported: building a graph for one raises a ValueError that says so.

  • A graph’s window starts at the organism’s first release in the table (idtrack.organisms.first_release: 48 for human, mouse and rhesus, 56 for pig, 91 for cynomolgus), for idtrack.build.DatabaseManager and the API alike (previously 48 in the API, the selected assembly’s first release in the manager).

  • idtrack.API.build() builds on the organism’s assembly order; the primary assembly is the preferred one that has the snapshot release.

  • The shipped external-database files of all five organisms include Ensembl release 116. ExternalDatabases.extend_modified_yaml extends a file to new releases (keeping a .bak of the file it replaces), and a graph build warns once about releases its file does not cover. Include must be a YAML boolean; entries for assemblies or releases that the organism table does not give the organism are left out with a warning (an error in a shipped file).

Harmonization (idtrack.harmonize.HarmonizeFeatures)

  • Each converted gene is one output feature, named by its Ensembl gene id at the target release; its name in the final database is a column (the first in sorted order, the others in <final database>_alternatives). A gene without a name there keeps a missing value and status converted_no_final_id: the final-database column never holds an Ensembl id (previously 58 % of pig rows converted to VGNC symbols had an Ensembl id there, unflagged).

  • Nothing is dropped silently: every output feature has var["idtrack_status"] and var["idtrack_reason"] (statuses in idtrack.harmonize.STATUSES). A dataset is converted on its own: an id that is n-to-1 in one dataset is no longer deleted from every dataset (previously 12 % of the counts of two pig datasets were lost this way). A feature that is a gene id existing at the target release is converted to itself (see “A gene id is its own answer”), not flagged ambiguous between its own later version and other genes its history reaches.

  • New arguments: merge="sum" adds up the input features of one gene ("flag", the default, keeps the feature that names the gene and flags the others), keep_unconverted, from_release_by_dataset (the release each dataset was annotated with), from_database_by_dataset (the database each dataset’s feature names are ids of), api (an idtrack.API whose graph is loaded).

  • New methods: feature_table, output_plan, conversion_report; the attributes matchings, feature_names, gene_names. Removed: get_idtrack_matchings_for_all_datasets, dict_n_to_1, unified_matching_dict, multiple_ensembl_dict, the removed_*/kept_* diagnostics, conversion_failed_identifiers, debugging_variables.

  • The result cache is one JSON file per dataset (idtrack_result_<project>_<dataset>.json), written atomically, with a header of everything it depends on (idtrack version, organism, final database, releases, source database, graph); anything else is recomputed. Caches of 0.0.5 are recomputed once.

  • organism is read from the graphs in the local repository when not given; snapshot_release defaults to the newest local graph of the organism; final_database defaults to the organism’s first symbol database (idtrack.organisms.SYMBOL_DATABASES: HGNC Symbol for human, MGI Symbol for mouse, VGNC Symbol for pig and the macaques). In 0.0.5 they defaulted to human and release 114.

  • idtrack.harmonize.HarmonizeFeatures.unify_multiple_anndatas() loses no obs column by default (#85): obs_join="outer" keeps every column of any dataset, missing (as a missing value of the column’s kind; integers and booleans become nullable) in the datasets without it; obs_join="inner" keeps the columns every dataset has. obs_columns_to_keep selects among the joined columns. Every input var column is kept (one column where the datasets agree on each feature, otherwise <column>_<handle>). Layers, obsm, obsp and shared uns entries are carried over, X keeps its dtype, raw is dropped with a warning. Values are no longer rewritten (no placeholder _PLACEHOLDER_NA_; text columns become categorical). feature_harmonizer returns the whole dataset re-indexed by the harmonised features.

  • Feature names are read from the files without loading them, checked (empty, not strings, repeated) before any conversion; mode, obs_join and merge are validated before any work.

Access to Ensembl

  • Access modes, set with the environment variable IDTRACK_ENSEMBL_ACCESS or idtrack.settings.configure_ensembl(access=...): auto (default: MySQL where its ports answer, the HTTPS dumps otherwise) and https (MySQL is never contacted). Both give the same tables, with the same values and column types. A MySQL port that fails is tried again after ten minutes; MySQL query errors are raised. See Network Access: MySQL or HTTPS.

  • A failed request is never read as “absent”: a release that cannot be listed, or a table that cannot be downloaded after the retries, raises (idtrack.errors.EnsemblDownloadError); previously such releases were dropped silently, and one failed request could select another primary assembly.

  • Ensembl REST requests (organism names, the latest release) are retried on timeouts, connection and SSL errors and the HTTP statuses 429 and 5xx (rest_attempts, default 3), with the timeouts connection_timeout (15 s) and reading_timeout (60 s; also used by the HTTPS dumps) of idtrack.settings.EnsemblSettings. After the last attempt idtrack.errors.EnsemblRestError (a ConnectionError) names the URL, the timeouts and how to raise them (#84).

  • idtrack.build.VerifyOrganism asks Ensembl REST for the species list at most once per process and only when a look-up needs it; fetch_organism_and_latest_release takes no timeout arguments.

  • Tables read from the HTTPS dumps are decoded as MySQL loads them (escaped tabs, newlines and backslashes), so such rows are no longer split or dropped. Building a pig graph from nothing takes 15 minutes (previously 73 minutes) and 0.65 GB of disk (previously 6.9 GB).

pandas 3 (#86)

  • idtrack works with pandas 2.3 and 3.x. 0.0.5 could not store a table with a text column under pandas 3, and DatabaseManager.create_ids then reported the misleading Table 'gene_stable_id' not found. Only a schema answer (idtrack.errors.EnsemblSchemaError: the release has no such table or column) leads to the older-schema fallbacks; any other error is raised as it is. Text comes back in the running pandas’ default text dtype; tables written under one pandas version are read under the other.

Dependencies

  • idtrack supports Python 3.12 to 3.15; Python 3.9, 3.10 and 3.11 are no longer supported (on Python 3.11 no anndata release writes .h5ad files with pandas 3).

  • Minimum versions are raised to releases that install on Python 3.12 and pass the test suite together: pandas 2.3 (and 3.x), anndata 0.13, numpy 2.1, scipy 1.14, h5py 3.11, networkx 3.2, PyYAML 6.0.2, PyMySQL 1.1.1, tqdm 4.66.3, PySocks 1.7.1; optional: biopython 1.81, torch 2.2, transformers 4.36. sparse is no longer a dependency. See pyproject.toml for the reason of each.

  • idtrack requires requests>=2.33.0 and urllib3>=2.8.0, the first releases without the vulnerabilities CVE-2026-25645 (requests) and CVE-2026-44431, -44432, -97687, -97688 and -97689 (urllib3).

Older snapshots (#71)

  • GraphMaker explains, when a manager is not at the newest release of its window, how to build a graph whose snapshot is an older release (API.build(organism, <release>, local_repository)); see “Working with an older Ensembl release” in Quickstart.

Track.version_info, the graph attribute version_info; EmptyConversionMetricsError (nothing raises it).

  • TheGraph: combined_edges, combined_edges_genes, combined_edges_assembly_specific_genes, get_active_ranges_of_id, node_trios, lower_chars_graph and node_name_alternatives (use idtrack.graph.TheGraph.combined(), idtrack.graph.TheGraph.active_ranges(), idtrack.graph.TheGraph.trios(), idtrack.graph.TheGraph.resolve_name()); the node attribute is_latest; GraphMaker.get_graph’s overwrite_even_if_exist (a rebuild always replaces the file).

Other changes

  • Track raises an idtrack.errors.UnknownOrganismError for a graph whose organism is not in the organism table (previously the assemblies were ordered by their numeric code); register the organism first.

  • Without an explicit assembly, DatabaseManager picks the highest-priority assembly that has the release it is made for, inside first_release/snapshot_release (e.g. a mouse snapshot at release 100 uses GRCm38).

  • DatabaseManager.create_available_databases lists the core databases of the organism’s configured assemblies within their release ranges, the same in both access modes; DatabaseManager.get_db("generegion") tells which genes of a release lie outside the reference sequence.

  • The self-tests of a graph (idtrack.checks.GraphChecks): every check (is_...) returns a idtrack.checks.CheckResult with holds (also its truth value) and details (what was compared and every violation found), where it returned True, False or a tuple. A check does not raise for what it finds: a table that cannot be read or a release without identifiers is a result that does not hold, with the error in its details. A database that the graph does not hold is refused before anything is converted, by the checks and by history_travel_testing: an idtrack.errors.InputError that names the argument and lists the valid databases, as the API raises for a wrong argument (previously history_travel_testing returned a report in which every identifier was lost or failed, and the name of a form was the only name it refused). The checks compare assembly by assembly at every release an assembly has (previously they raised at the first release of an earlier assembly, or reported every graph with more than one assembly as inconsistent), report identifiers that only the graph has as well as those it lacks, and count a gene that has an id in a database and is not converted to it. random_dataset_source_generator returns None when nothing can be drawn (previously the tuple ("", -1, -1)), and history_travel_testing_random_arguments_generator raises an idtrack.errors.InputError after 100 attempts.
